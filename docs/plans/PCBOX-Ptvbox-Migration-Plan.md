# PCBOX 与 Ptvbox 双向迁移

2026年11月22日用户确认：“需要，两端都支持迁移”。此文件确认新增范围与实施约束，不代表功能已交付。

## 确认范围

- [x] 用户确认PCBOX → Ptvbox、Ptvbox → PCBOX双向迁移。
- [x] 同时保留PCBOX换电脑、Ptvbox换设备的同端迁移需求。
- [ ] 两端提供同一密码加密备份格式的导出、导入预览和确认入口。
- [ ] 凭据、链接/订阅、站点稳定标识/开关/优先级、资料手动关联、收藏、想看/在看/已看、单集标记、观看进度与可对应的播放设置互转。

## 本轮只读核查

- PCBOX的SettingsPage.OnBackup目前仅压缩用户目录根层的JSON文件；TmdbCredentials、SubtitleCredentials、ServiceCredentials分别使用DPAPI保存，现有ZIP不能作为完整可迁移凭据备份。
- Ptvbox 0.5.3已有PTVBK1密码加密备份，包含Android schema3表、偏好和经Keystore读取的凭据，但未实现Windows格式转换。
- Windows的CatalogItem、Keep、History与Android的Work、Watch、独立状态表不同；字段和作品/季集身份需要映射，不能按片名粗暴合并。
- 本轮未读取用户凭据内容、未导出真实用户资料、未改动PCBOX或Ptvbox业务代码，未构建/发布新版本。

## 实施顺序与约束

1. 建立版本化的跨端数据契约和映射清单。沿用毫秒精度；作品采用外部平台ID与类型，剧集增加季/集身份。来源key保持原值，不因显示名称重建收藏或进度。
2. 扩展现有加密容器并保留旧格式读取能力。DPAPI/Keystore仅在原设备解密，备份由用户密码保护，目标设备重新用自己的安全存储保存。密钥不出现在日志、预览和发布包中。
3. 实现两端导出、只读预览与导入确认。预览显示记录数量、冲突和不支持项，不显示密钥。默认保留已有凭据与较新进度；替换配置须明确选择。不清空用户库，不删除原备份入口。
4. 保留平台专属字段，注明“已保留、当前平台不应用”，避免往返迁移后丢失。电脑窗口位置、Android TV频道ID、设备路径、系统登录会话等不得强行套用；硬件/账号要求重新授权时明确提示。
5. 先用虚构凭据和隔离用户库完成密码、加密、双向与往返测试，再进行两端UI验证与打包。PC原生验证使用TVBOX_PC_DATA_DIR独立QA目录；ATV只用隔离模拟器，真机需本轮授权。

## 验收清单

- [ ] PC → TV：凭据可被目标端读取使用，订阅/站点身份、收藏/状态/单集和毫秒进度正确。
- [ ] TV → PC：同样验证，不能仅以JSON解析或导入成功提示作为通过。
- [ ] PC → TV → PC、TV → PC → TV：可共享数据及保留的专属数据不丢失。
- [ ] 已有记录冲突：较新进度和默认保留凭据生效；显式替换行为与预览一致。
- [ ] 错误密码、损坏/过大文件、非法路径、未知版本和字段冲突在写入前拒绝；中途失败可恢复。
- [ ] 旧Ptvbox备份继续可读，旧PC备份入口保留，签名和应用身份不变。
- [ ] 两端报告分别列出支持、保留未应用和无法迁移项；APK/PC包本地交付，未获上传要求不发布。

本需求属于后续实施范围。0.5.3现有APK尚不支持PCBOX与Ptvbox互导，不能将原始Windows凭据文件直接复制到Android使用。
