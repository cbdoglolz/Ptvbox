## 二、版本路线

### 0.5.6：动画资源与播放信息整合

目标：把当前已经写进代码的动画、弹幕、轨道、字幕包、观看标记和直播小屏改造收口成可交付版本。

本版必须完成：

- [x] 验证 18 个动画源的搜索与详情解析；记录真实可播放样本和失败样本。
- [x] 验证季度、星期和北京时间排期；无排期作品只显示在“全部”。
- [ ] 验证动画源与普通/国际资源站不会互相串片，季数和集数不匹配的结果不能冒充当前集。
- [ ] 验证多音轨语言、声道、格式显示，并确认续播恢复上次音频选择。
- [ ] 验证字幕包先展开、字幕文件再加载；下载失败必须给出可理解提示。
- [x] 验证弹幕区域、飞行距离、字号和即时保存；默认全屏移动。
- [x] 验证单集状态弹窗在横屏模拟器一屏可操作，不再遮挡底部文字。
- [x] 验证直播页表头可滚走、加载有占位、没有空白等待页。
- [x] 完成 JVM、XPath、布局触摸、在线季度、逐站搜索和动画首帧检查。
- [x] 输出 0.5.6 报告与签名通用/ARM APK。
- [ ] 真实电视和真实手机安装测试。

本版不包含：完整双向迁移、全量体育资源重写、HDR 输出和原生手机界面。

### 0.5.7：数据连续性、站点维护与更新安全

目标：换设备、换电脑和站点规则更新时不丢数据。

本版第一批已先完成导航、详情、播放器、历史、动画检索和 HDHUB 直连修复；下方数据连续性工作仍待继续。

计划实现：

- [ ] 定义 PCBOX/Ptvbox 共用、版本化的加密迁移格式。
- [ ] 双向迁移凭据、订阅和链接、站点 key/开关/优先级、手动匹配、收藏、三态、单集标记、进度和可兼容播放设置。
- [ ] 导入前显示数量、冲突和不支持项，不显示密钥；默认保留较新进度。
- [ ] 支持错误密码、损坏文件、旧版本备份和导入失败回滚。
- [ ] 站点页增加单站、整组和全部连接检测；显示最近检测时间、失败原因和解析能力。
- [ ] GitHub 源维护检查先显示新增、修改、移除和健康状态，再由用户确认应用。
- [ ] 更新失败时保留上一份可用源，可回退。
- [ ] 企业微信只推送真正的功能更新详情，不发送链接；测试构建和仅检查时间不通知。

验收重点：PC → TV、TV → PC、PC → TV → PC、TV → PC → TV 四类往返数据不丢失，原签名、原站 key 和旧备份继续工作。

### 0.5.8：资源兼容专项收口

目标：把“类型接入了”变成“有真实样本可搜索、可出首帧”。

计划实现：

- [ ] 私人 TVBox Jar 逐站检查搜索、详情、解析、空地址和首帧。
- [ ] 补齐尚未适配的 JS 规则，并保留明确的失败原因。
- [ ] 国际高清站点逐站检查中文/外文标题、别名、季集、容量、HDR 标签和多版本。
- [ ] 动画规则支持独立更新、站点状态、失败回退和启动同步检查。
- [ ] 直播/体育补齐分类分页、回放、未开播、HLS/FLV 断流、平台兼容线路和当前比赛返回。
- [ ] 网盘扫码补齐授权缓存、二维码过期、重新打开、多个网盘切换和 1/3 计数。
- [ ] 修好资源站搜索排序：分组优先级先于普通兼容站，高清优先时同类按容量从小到大，可叠加分辨率筛选。
- [ ] 增加站点分组优先级设置和 100 站以上虚拟化列表，避免打开、滚动和点菜单卡顿。

验收重点：每个接入站点必须有本版本的真实样本和失败记录；支持站点数量本身不能作为完成证据。

### 0.6.0：高级播放能力

目标：完成字幕、音轨、弹幕和显示能力，不依赖“看起来有按钮”。

计划实现：

- [ ] 字幕优先级按 TMDB/IMDb 精确 ID，再按作品别名、季集、年份和发布版本匹配。
- [ ] 字幕结果明确显示语言、来源、格式、FPS、季集、版本和压缩包状态。
- [ ] 支持 SubDL、ASSRT、OpenSubtitles 和用户后续可配置来源；保留失败诊断、有限重试和下载额度保护。
- [ ] 自动加载上次字幕和时间偏移；字幕样式实时预览，支持字号、字体、粗细、颜色、背景和透明度。
- [ ] 提供基础自动时间轴建议，并保留手动提前/延后和单句锚点。
- [ ] 弹幕按动画季度、集数、版本自动匹配；区分可播放、无版权、服务失败和公共回退。
- [ ] 验证多音轨语言、声道和格式，续播恢复音轨、字幕、倍速、画面比例和音量。
- [ ] 片头片尾、广告标记、小窗拖动和变更比例缩放。
- [ ] 检测设备 HDR/Dolby 能力，提供 HDR、SDR 和设备支持范围内的映射选项；不支持的设备明确提示。

验收重点：每个功能必须有真实媒体样本；错季字幕、无内嵌字幕、不同时间轴和多格式视频都要覆盖。

### 0.6.1：TV 交互与性能专项

目标：解决功能变多后页面卡顿、焦点跳动和小窗口遮挡。

计划实现：

- [ ] 100 站以上站点列表、海报墙和设置页虚拟化及增量刷新。
- [ ] 搜索、详情和播放页的焦点位置恢复，异步结果插入后不回顶部、不把焦点跳到错误卡片。
- [ ] 播放器小窗按窗口尺寸自适应，允许拖动和四角锁比例缩放，不出现控制条盖住画面主体。
- [ ] 测量方向键反馈 P95、慢帧比例、源扫描和海报解码，目标是 60Hz 设备方向键 P95 ≤50ms、导航慢帧 <1%。
- [ ] 按现有配置上限做 20 路并发扫描压测，确认不会挤占 UI、内存或中断当前播放。
- [ ] 在手机横屏、模拟器、小尺寸窗口和 TV 分辨率检查长标题、100 站、长弹幕和多行状态。

验收重点：以本轮设备采样为准，旧截图或单纯编译通过不能证明性能达标。

### 0.7.0：稳定性、发布自动化与 ATV 基线候选

目标：形成可以长期使用和升级的 ATV 基线。

- [ ] 连续播放、切集、切源、暂停恢复、进程退出和断网恢复。
- [ ] 30 轮遥控器焦点往返和页面位置恢复。
- [ ] 配置、收藏、进度和站点升级后保留；失败恢复入口可用。
- [ ] 图片缓存上限、内存回收和低配置 TV 验证。
- [ ] ATV 个性化频道和接下来播放的真实 TV 主屏验证。
- [ ] GitHub 构建、签名、草稿 Release、覆盖升级和版本哈希端到端验收。
- [ ] PCBOX 与 Ptvbox 剩余差异完成正式对照，不再以“大部分完成”描述全量对等。
- [ ] 主版本签名 APK 提供 ARM 和通用包，附完整报告。

验收通过后可以考虑发布 `1.0.0` 作为 ATV 稳定版。是否进入 1.0 仍由用户验收决定。

### 独立后续阶段：原生安卓手机版

原生手机版应作为独立阶段，不把横屏 ATV APK 直接称为手机版。可复用数据、搜索、资源和播放核心，但手机端应重新设计：

- 竖屏导航和底部操作栏。
- 单列/双列海报与手势返回。
- 原生手机播放器和系统小窗。
- 手机端配置、收藏、进度和密钥安全迁移。

## 三、每版固定交付规则

每个版本统一按以下顺序完成：

1. 先完成本版功能，不提前把下一版未做功能写成完成。
2. 运行与改动相关的专项测试，再运行全量回归和构建。
3. 没有直接连接机顶盒测试时，交付签名 APK 给用户手动安装。
4. 报告分开写明“功能实现、模拟器证据、真实设备证据、在线资源证据、失败项”。
5. 附要求清单：完成项打勾，部分完成、未开发和未验收项留空并写备注。
6. 列出本版未做内容、剩余风险和下一版范围。
7. Release 保持草稿，由用户确认发布；企业微信只通知真实更新内容且不带链接。

## 四、当前建议的下一步

先完成 0.5.6 的资源实测和交付包，不直接跳到 0.6.0。0.5.6 通过用户测试后，再进入 0.5.7 的跨端迁移和站点维护。原因是迁移会触及收藏、进度、站点和凭据，必须建立在资源身份和播放行为已稳定的基础上。

若用户临时改变优先级，例如要求先修体育或先完成字幕，则只替换当前下一版本的目标；已经完成且通过回归的功能继续保留，不回退既有数据或可用功能。
