# Ptvbox 基于 PCBOX 1.1.4 的界面与电视交互改造方案

日期：2026年11月20日。更新：用户随后批准“开始0.30”，本轮已实施0.3.0核心界面改造，详见0.3.0交付报告；本方案剩余版本仍待逐轮审核。下文保留制定方案时的边界和目标，不将目标当成全部已完成。

目标：让用户在电视上看到熟悉的PCBOX页面、内容顺序、图标与操作逻辑，再用遥控器顺畅操作。保留Ptvbox 0.2.2已经接通的能力，逐步补齐PC功能。首轮交付应是完整的核心界面改版，不能再把临时控件排列当作界面迁移完成。

## 1. 基准及执行边界

| 基准 | 本方案采用的内容 | 边界 |
|---|---|---|
| 本地PCBOX 1.1.4 | 页面结构、品牌素材、配色、卡片、评分、筛选、控件顺序、操作反馈与业务行为 | 已核对项目版本为1.1.4；本轮读取的是当前本地源码，不等同已核验所有已发布二进制行为 |
| Izuko TV | 遥控器按键、分层面板、焦点恢复、播放器状态管理、电视设置组织方式 | 参考上游公开文档，不整体替换成其Animeko/Bangumi业务，不借用开发者凭据 |
| Ptvbox 0.2.2 | 已有Android播放、数据、密钥、季集、Jar与系统桌面集成 | 采用已有实现继续改造；已验证的功能必须列入回归 |
| 用户原开发总档案 | 分阶段审核、数据保护、TV/手机边界、性能目标 | 页面视觉及顺序采用本轮明确的PCBOX基准；原有保护和阶段验收纪律继续执行 |

本轮只交付方案文档。不修改Windows PCBOX，不操作机顶盒，不提升版本、不重打包、不上传。Ptvbox代码改造在用户批准对应阶段后实施，每阶段三个步骤完成后提交审核。以下版本号是建议排期，不代表已发布或已获准连续开发。

“接近PCBOX”的验收分为三项：

1. **视觉**：内容层级、布局比例、颜色、图标、圆角、间距、评分与标签位置有逐项对应。
2. **行为**：同一操作产生与PC相同的业务结果，例如收藏即时更新、普通/高清搜源范围、恢复同集同版本、直播不进点播搜索。
3. **电视操作**：方向键能到达所有关键操作，返回层级明确，关闭面板回到原焦点，异步结果不抢走用户焦点。

不承诺把Windows坐标逐像素缩放到电视。文字可读性、焦点热区、屏幕安全边距及遥控器操作需要调整；这些差异在对照表标明，不作为另起一套视觉样式的理由。

### 3.1 统一视觉组件

先建立一套组件，再改页面，防止各页继续各写一套。

- 从PC提取深色/浅色主题、表面色、强调色、次级文字、边框、圆角与间距，统一命名；不再散落硬编码颜色。
- 复用用户PCBOX的Logo和字标素材风格，矢量图标转换到Android固定画布；星形、停止、音轨、字幕等图形居中。应用现有名称和安装身份不随本次视觉改造擅自更改。
- 海报、评分条、未上映标记、观看状态、来源标签、通知条、筛选按钮、设置行各有唯一组件。
- 评分明确区分“未配置/未匹配”和“已匹配但暂无分数”：前者灰褐半透明，后者保留来源色与短横；浅色主题用浅色底框。
- 所有点击项拥有独立焦点/按压态。TV常用操作目标热区以48dp起步，必要时扩大热区而不是把图标一起放大。
- 1080P作为首轮对照尺寸，增加720P与4K布局检查；分辨率不直接决定卡片数量，按实际dp宽度和可读性适配。

### 3.2 首页和侧栏

PC当前外壳为起点：顶部品牌与搜索，侧栏首页、正在播放、电影、电视剧、动漫、纪录片、综艺、资源、直播、搜索、收藏、历史、体育，底部设置与站点。TV分组展开方式可简化，但不遗漏入口或随意改变用户熟悉的分类。

首页保留PC的来源入口、分类标签、横幅、继续观看横排和主海报墙；分类页继续使用网格，不把所有页面一律改成横排。横幅只提供进入资料/片源入口，海报确认直接进详情，默认不增加Izuko的“先预览再按一次才进详情”步骤。

正在播放卡片使用“标题与季集”“时间进度”“播放/暂停和停止”独立区域。标题可两行，按钮不能覆盖文本或时间。展开侧栏不得让视频或整面海报重新测量。清空播放会话后隐藏正在播放卡片。

未上映默认关闭。切换开关保留当前分类、筛选、滚动位置和焦点锚点；确实被筛掉的条目回退到邻项。未上映海报左下角及详情均标记。日期来自实际资料，缺日期不能捏造1月1日参与排序。

### 3.3 详情及单集

以PC详情模块顺序为准：顶部背景/作品标题；海报与资料操作；季与单集；作品资料与播放线路；出品与播出；剧情；人物；同系列/相关版本；相似推荐。不同作品无数据的模块自动隐藏，不能留大片空框。

豆瓣和TMDB评分各自提供始终可见的“手动匹配”“清除匹配”。修改任一平台只变更其关联，不清除另一平台；评分、人数、海报、人物在同页即时更新。自动匹配使用原名、又名、年份、类型和季数，歧义显示候选，不把不同年份同名片硬合并。IMDb只在有可靠数据时独立显示。

季集目录与元数据并行：没有Key也能展示资源站已知集数；有TMDB数据补充真实单集剧照、集名、评分和日期。单集卡片保留收藏、已看、进度，缺单集评分显示暂无评分，不能挪用整剧评分。

普通/高清片源采用紧凑自适应网格。PC宽窗口至少四列的密度在TV上按可读性换算，不能硬塞四列小字。每张只放关键来源、版本、分辨率、容量、已识别HDR/Dolby/Atmos等标签及播放动作。未探测的标签显示未知，不从文件体积猜画质。

分辨率筛选支持多选，选中绿色；在搜索过程中增量更新。已知容量从小到大、未知容量末尾，详情和播放器线路面板一致。自动选源策略另行判定，不因排序把当前选中条目或焦点推回首项。

### 3.4 播放器

正常画面占满可用区域，黑边需区分片源比例与播放器外边距。支持FIT、FILL、ZOOM，后续补原始/16:9/4:3；保持上次选择，不能默认拉伸所有片源。

顶部从左到右划分探测进度与暂停、独立通知区、速度/高清优先、重新检测、收藏。通知优先一行，必要时两行；同一任务只更新一条，不叠起大横条遮画面。重新检测使用真实已完成/总数，保留当前播放。

底部顺序沿用用户PC要求：

`上一集 → 播放/暂停 → 下一集 → 停止 → 选集/直播线路 → 播放源 → 倍速 → 画面比例 → 字幕 → 音轨 → 弹幕开关 → 弹幕设置 → 广告标记 → 动态范围`

右端固定一组：`音量 → 跳过片头片尾 → 小窗/画中画 → 全屏`。TV全屏按钮可用于退出沉浸播放或回到浏览会话；不照搬Windows窗口最大化。窄屏把中间低频操作收进“更多”，保持相对顺序和右侧分组，不能把按钮裁掉或压住时间轴。

恢复播放优先保存的作品、季集、来源版本、清晰度、音轨、字幕及偏移。旧临时URL到期时重新解析同一资源；同一站点的720P不能冒充上次1080P。确实没有原版本时显示明确的替代结果，不静默降级。

字幕搜索运行时右上角保留紫色状态，即使工具栏隐藏也可见；完成结果停留约7秒，并直接出现在CC第一层顶部，标出数量及上次使用。样式面板保留中文/英文实时预览，按用户最新要求以约40%不透明度作为起点，叠加强调色保证可读性。时间轴调整保存到对应影片/单集/版本，不能跨版本盲用。

播放器面板只切换当前一层，统一管理打开状态、焦点与返回，不再依赖多个无关联布尔变量互相覆盖。未接入的在线字幕、弹幕或HDR能力在阶段清单注明；实际发布不能以外观相同的空按钮宣称已实现。

### 3.5 设置、站点与手机配置

设置左侧分类：外观与海报、影视资料、播放器、字幕、弹幕、站点与订阅、直播体育、网盘/NAS、网络与缓存、用户数据与同步、更新、关于。右侧为内容，不做无止境的全宽单列输入框。返回先退出设置子面板，再回设置分类，最后回原页面。

所有密钥输入框不回显原值，旁边显示绿色已保存状态；保存/验证/删除分开。保留已有加密与验证回调，扩展手机台输入字幕服务、弹幕和网盘设置。手机控制台增加搜索、播放操作与状态，继续使用有时限的配对授权，不公开读取凭据。

站点列表采用虚拟化紧凑行，数据更新只刷新对应站点。按当前PC/用户分组展示私人TVBox、原始TVBox、国际、动画；支持分组优先级、单站/整组检测、规则检查和确认更新。播放线路面板中的“启用站点/关闭站点”与后台同一状态，关闭后不再启动新请求，迟到结果也不得重新加入候选；当前播放由用户明确切换或停止。

检测按“配置可读取、搜索可响应、解析出媒体、实际出画面”分层显示，HTTP200不等同可播放。更新先预览来源版本、变更和本机检测结果，由用户确认激活，保留上一可用版本。上游引擎代码变化不能当作JSON规则直接覆盖安装。

### 3.6 搜索、新番、直播与体育

搜索保留片名/原名/别名和年份/季集约束，使用已关联作品ID辅助建立别名；资源站不支持ID时仍需发送其接受的标题。首字母检索先覆盖本地缓存；在线索引没有来源时明确边界，不能直接把字母当中文发给所有站点。语音不可用时回退屏幕键盘和手机输入。

新番按冬春夏秋、年份和周一到周日组织。星期按钮有可靠数据才显示更新部数；支持精确时间时标出时区，统计与显示使用同一时区。缺播出时间不编造时间；进入作品后走统一详情和搜源，不维护第二套收藏进度。

体育与直播独立于点播：频道/比赛名称完整换行、队徽和Logo完整适配、继续频道位于标题下并置前。选集位置改为全部直播线路，可合并分页的中文/英文/原声线路；返回原比赛详情，再返回原站点原列表位置。播放失败展示解析/连接/解码原因，绝不自动转点播资源站搜索。

网盘扫码可重新打开、刷新，显示来源名称和多网盘序号；授权加密缓存并尊重服务端失效。不能承诺所有网盘扫码一次固定维持一个月，过期提示按实际服务响应处理。

## 4. Izuko式遥控器操作规范

以下是为PCBOX行为制定的目标映射。参考Izuko的按键与焦点设计，保留本项目“海报确认进详情”和“应用内浏览保留播放”的既定语义，不继承与此冲突的默认动作。

| 当前状态 | 操作 | 目标行为 |
|---|---|---|
| 海报墙 | 方向键 | 按相邻海报移动；行首左键进入侧栏，末端不意外绕回首项 |
| 海报墙 | 确认 / 长按确认 | 进入详情 / 收藏、状态等动作面板，避免把嵌套小星星变成必经焦点 |
| 详情 | 返回 | 先关面板，再回来源页原卡片、原分类及滚动位置 |
| 播放，控制隐藏 | 确认 | 暂停/播放；独立媒体播放键同义 |
| 播放，控制隐藏 | 上 / 下 | 打开播放源 / 显示时间轴和工具栏 |
| 播放，控制隐藏 | 左右 / 连按长按 | 进入快退快进预览，建议5秒基础步进；确认提交、返回取消 |
| 播放，控制隐藏 | 长按确认 | 临时倍速，可设置2倍/2.5倍，松开恢复原倍速，直播不误触 |
| 控制显示 | 方向键与确认 | 在按钮/时间轴间移动并执行，不同时触发隐藏层的快进 |
| 控制显示 | 返回 | 隐藏控制；不能一按退到首页 |
| 子面板打开 | 返回 | 关闭当前面板，焦点回到打开它的按钮 |
| 控制隐藏 | 返回 | 回当前作品/比赛详情，应用内播放会话保留 |
| 播放器任意面板 | 长按返回 | 直接收起面板与控制回画面，不关闭应用；避免长短按重复执行 |
| 停止 | 确认 | 保存进度、停止并清空播放资源，回当前作品详情或该直播的原入口 |
| 系统HOME/其他应用 | 默认行为 | 保存进度并停止/释放；后台播放是单独可选能力，默认关闭 |

PiP明确开启时按Android的画中画生命周期处理，不能误判为普通HOME退出而把用户主动进入的小窗停掉。后台开关启用时使用MediaSessionService及对应系统要求；不依赖隐藏Activity持有解码器。

焦点恢复统一存稳定作品/单集/站点ID、分区和滚动锚点，不只存列表下标。目标未组合时等锚点附着再送焦；用户已按方向键移动则取消迟到的恢复。弹窗关闭焦点短暂为空时沿用上一层级，不能凭空把用户送到页面首项。加载中、确实无目录、加载失败分开处理。

Izuko公开文档说明其TV界面独立、播放器采用分层按键，并记录异步焦点恢复和面板空焦点问题。本方案采用这些交互原则，具体实现仍对照Ptvbox现有会话与数据接口。[上游README](https://github.com/GrahamZen/izuko-tv/blob/main/README.md)、[TV维护文档](https://github.com/GrahamZen/izuko-tv/blob/main/FORK.md)。直接引入代码前固定上游提交、列出文件来源及许可，保留应有声明。

## 5. 实现结构与数据保护

保留Kotlin、Compose、Media3、SQLite和Keystore。按本次页面改造逐步拆分现有MainActivity/PtvModel，不先大规模更换底层引擎或数据库。

建议形成三组职责：

- **界面与输入**：主题/图标/卡片等公共组件；首页、详情、播放器、搜索、设置、站点独立页面状态；TV按键路由和焦点恢复。
- **会话与业务**：唯一播放会话、搜源调度、作品匹配、季集、观看数据、配置变更。触摸、遥控器、手机控制台调用同一组动作。
- **数据与平台**：现有资料接口、Jar服务、后续JS/字幕/弹幕适配器、SQLite、Keystore、TvProvider、Android播放器及系统后台服务。

组件是否显示、是否可操作由真实能力状态决定；UI不能自行构造成功结果。界面/网络/状态层分离后，后台候选刷新不应造成整棵海报墙或播放线路列表重建。

必须保留：包名和签名；用户订阅和站点稳定key；开关与分组优先级；收藏和三态；毫秒原始进度及对外秒制转换；单集身份与季目录隔离；手动关联；密钥和登录会话；ATV频道及深链。后续同步以独立授权为前提，不触碰PC个人数据库。

SQLite变更使用带版本的增量迁移、备份和失败回滚；不能清库重建。新UI按页替换，旧路由在新页面通过验证后再切换。需要删除或大幅改变正常功能时，列出具体影响，按用户既定要求取得明确答复再执行；等待期间做其他独立项目内容。

HDR/Dolby优先检测片源、显示设备及Android输出能力；HDR显示和SDR色调映射需要真实硬件验证。不能承诺把Windows的动态范围按钮、解码器调用或Dolby Vision输出原样搬过来，不能以单纯调亮画面代替映射。无相应硬件能力时准确提示限制。

## 7. 验收方法

视觉对照冻结PC1.1.4素材与布局，同片名/同数据分别截取首页、分类、详情、季集、播放器、线路/字幕面板、设置和站点。每项标记“已还原、TV适配差异、尚未实现”，不能只附一张漂亮首页截图。

至少覆盖深色/浅色、1080P及小尺寸、长中文/长英文片名、零结果/加载/失败、无Key、未匹配/无评分、未上映、1集/多季、多线路以及100站列表。页面初始/展开/面板打开状态都需检查。动态数据不同的截图不能直接做像素相似度结论。

遥控器记录操作脚本与可见落点：从侧栏到海报、详情到季集、播放到选源/字幕、返回原卡片、关闭弹窗、异步新增结果及断网恢复。鼠标/触摸保留同等核心操作。快捷操作不能让长按结束时再执行一次短按。

性能采用原档案目标：60Hz设备上方向键反馈P95不超过50ms、导航慢帧比例低于1%。记录采样方法、场景、帧数、设备模式和原始证据；软件模拟器或无法测到的指标不能替代实机达标。重点检查UI线程读库、进度高频刷新、海报解码、列表重组和源扫描竞争。

每版交付：本版完成打勾、部分/未做留空、PC差异表、模拟器/实机分别记述、问题和下版范围、签名APK与校验、Markdown报告。编译通过、测试数或APK可安装不代表产品阶段通过。每轮完成后交用户审核，再进入下一轮。
