# 分类片源优先级方案

日期：2026年11月26日  
目标：让中文剧、外语片、动画等不同类型使用不同的资源站搜索顺序，同时保留用户手动开关、原播放续播和失败回退。

> 0.9.0状态：七类分类、各分类分组顺序编辑和分波搜索已实现。同一分组内逐站拖拽顺序仍未实现。

## 当前实现与限制

- 现有`Sites.ordered()`只按站点分组优先级排序。
- `PtvModel.scan()`会按该顺序启动检测，但所有站点仍会并发进入同一个信号量，因此“排序”主要影响启动先后，不是严格的分类优先搜索。
- 要做成用户理解的“中文剧先找私人订阅，外语片先找HDHUB，动画先找动画源”，需要改成“分波搜索”：每类片先跑第一优先级站点，短时间没有足够候选再进入下一波。

## 建议的内容分类

| 类型 | 判定依据 | 默认优先级 |
|---|---|---|
| 中文真人剧集 | `kind=tv`，语言为中文，非动画 | 私人订阅 → 默认点播 → 中文综合站 → 国际站缓退 |
| 中文电影 | `kind=movie`，语言为中文，非动画 | 私人订阅 → 默认点播 → 中文综合站 → HDHUB缓退 |
| 日本/韩国真人影视 | 语言为日语/韩语，非动画 | 私人订阅 → HDHUB/国际站 → 默认点播 |
| 欧美/英语影视 | 语言为英语或其他欧美语言 | HDHUB/国际站 → 私人订阅 → 默认点播 |
| 动画 | `genres`含动画或来自动画季度目录 | 动画资源 → 私人订阅 → HDHUB/国际站 → 默认点播 |
| 纪录片/综艺 | `genres`含纪录片或综艺 | 私人订阅 → 默认点播 → 中文综合站 |
| 未识别 | 缺少语言、地区或类型 | 用户现有分组优先级 → 全部已启用站点 |

直播与体育不混入点播规则，继续使用直播源独立排序。

## 规则结构

建议保存为版本化 JSON：

```json
{
  "version": 1,
  "rules": [
    {
      "id": "anime",
      "groups": ["动画", "私人订阅", "国际"],
      "siteKeys": ["kazumi_girigirilove", "hdhub"],
      "minCandidatesBeforeNextWave": 3,
      "waveTimeoutSeconds": 8
    }
  ]
}
```

- `groups`决定分组优先级。
- `siteKeys`允许把某个具体站点提到更前或放到末尾。
- 站点被用户关闭时，任何规则都不能重新启用它。
- 原站点恢复、同清晰度续播和“已标记广告站点降级”继续优先于普通同类排序。

## 搜索流程

1. 先根据作品语言、国家、类型和季集目录判断内容类别。
2. 生成第一波站点列表。
3. 使用当前“搜索并发”路数检测第一波。
4. 达到最低候选数，或达到单波超时后停止继续等待，进入下一波。
5. 全部失败时自动回退到其他启用站点，不能因为分类规则导致无结果。
6. 分类结果和站点健康状态缓存24小时；作品语言或手动匹配变化时重新分类。

## 设置界面

新增“分类选源”页面：

- 每一类显示“上移/下移/恢复默认”。
- 分组和单站都可调整。
- 显示最近检测结果、失败原因和平均首帧延迟。
- 提供“用当前作品测试”按钮，只预览排序，不自动播放。
- 用户现有分组优先级保留为“未识别类型”的后备规则。

## 可行性

可以实现。现有`Work`已经包含`kind`、`genres`、`facts.languages`、`facts.countries`和`imdbId`，`Site`也已有稳定`key`和`group`，不需要破坏性数据库迁移。

主要改动集中在：

- 新增`ContentTypePolicy`：内容分类。
- 新增`SourceRoutePolicy`：读取并验证分类规则。
- 改造`PtvModel.scan()`：从“按排序一起并发”改成“分波并发”。
- 设置页增加规则编辑和测试。
- 用虚拟站点、延迟响应和多语言作品做回归测试。

该功能应在当前设置页和播放器稳定后单独做成一个版本，避免同时改动焦点、配置和数据迁移。未完成逐站真实首帧验证前，只能称为“排序策略已实现”，不能称为“所有分类来源可用”。
