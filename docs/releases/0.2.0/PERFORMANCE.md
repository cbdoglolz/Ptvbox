# 0.2.0 性能记录

结论：完成了阻塞访问路径重构，**尚未通过流畅性验收，未证明比0.1.0快**。此次没有真实盒子授权，不提供机顶盒达标结论。

## 已落实的代码变化

SQLite与JSON操作转入后台Repository；UI消费批量状态快照。每3秒进度写入不再递增整页revision。站点配置读取/解密移到后台。目录请求受6路并发、单站12秒超时约束，与播放器探测分开。导航覆盖层不重新分配内容宽度，横行按需绘制。

这些是可核对的实现变化，不能单凭静态代码把历史卡顿归因于某一处。

## 本轮采样

同一独立API30 x86模拟器，软件GPU，1920×1080/320dpi/2048MB。旧、新签名Release各启动一次；内容就绪后重置gfxinfo，发送200个方向键事件（右60、下40、左40、上60），没有确认/播放动作。新旧首页结构与网络内容不同，单次样本且没有严格同库/同焦点轨迹，因此仅作诊断，不是受控性能对比。

| 原始指标 | 0.1.0 Release | 0.2.0 Release |
|---|---:|---:|
| 单次冷启动TotalTime | 726ms | 869ms |
| 导航绘制帧 | 101 | 97 |
| gfxinfo帧耗时P95 | 34ms | 42ms |
| gfxinfo帧耗时P99 | 73ms | 121ms |
| 报告的Janky frames | 97/101 | 97/97 |

软件GPU样本仍有慢帧，新包这些数值更差，不能标注性能优化已达标。尤其**gfxinfo P95不是按键到焦点反馈的P95**，没有关联输入时间与呈现帧的记录，不计算输入延迟。原始统计完整保留，不删除异常值。

较早Debug冷启动4.11秒及方向键记录同时受到主机Release编译竞争影响，单独保存在 `cold-start-debug.txt`、`gfxinfo-debug-navigation.txt`，不能和Release数值混用。
