## 原因与修复依据

1. **首页另一评分常为空**：旧逻辑主要在ProviderRatingRows详情组件拉取，首页只消费当前提供方列表。独立的PresentationQueue050现在由可见卡片/横幅触发，并持久缓存两平台结果。
2. **推荐海报过大/裁切**：旧详情主网格196dp列与CinemaPoster自身宽度约束混合，推荐图片仍使用Crop。现在推荐独立138dp横排，图片使用Fit。
3. **私人Appgz本轮失败**：首次回归未出帧，诊断为插件服务返回IOException timeout；对照0.4.0网络策略未变，模块加载下载位于站点搜索包装前，电脑访问模块能返回有效ZIP。Jar下载限时与可验证本地缓存修复后，Appgz再次实播1080P/同版本续播通过；再开测试会话确认缓存文件未被重写且仍可播放。失败日志保留为private-play-first-failure.txt，不能冒充通过记录。
4. **“网络直播”插件失败**：实际homeContent返回HTML而非JSON，抛出“Value <!DOCTYPE … cannot be converted to JSONObject”。模块地址本次电脑请求返回200有效JAR，不能据此断言Cloudflare或整个订阅失效。该插件频道仍未可用，现用配置保留；需继续定位插件内部上游返回。

TMDB图像按其官方语言字段选图，poster语言回退和images过滤的区别参见[图像语言说明](https://developer.themoviedb.org/docs/image-languages)。TV导航采用焦点可见、方向键移动及确认进入，参见[Android TV焦点指南](https://developer.android.com/design/ui/tv/guides/styles/focus-system)。这些规则不代替本地测试。

## 保留与风险

- 默认32站文件逐字节保留，新增国际站放独立资产文件；现用私人52站保留，预期总数由84变85。
- SQLite仍为版本3；新增presentation_v5只是可丢弃元数据缓存表，不替换用户表。缓存不进入用户凭据或签名备份。
- 中文海报/艺术字需要TMDB Key和可靠作品关联；无法唯一匹配保持原资料。缓存逐步填充，首次不会瞬间齐全，网络失败保留原画面。
- 直播临时地址可能过期，提供刷新；仅保存最近频道/线路身份，不承诺上游授权永久有效。磁力、DRM和需网页嗅探的资源不伪装成HTTP可播。
- 模块缓存位于Android code cache，系统清理/覆盖升级可能要求重新下载；同引用15分钟复用，更新引用或MD5后重新验证。不把旧模块自动当作所有上游已更新。
- 新版Android/TV硬件、省电策略、真实手机WiFi、长期内存与性能仍待实机，模拟器不能证明低配电视达标。
