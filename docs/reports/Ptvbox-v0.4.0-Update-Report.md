# Ptvbox 0.4.0 本地交付与PC对照报告

日期：2026-11-21。范围：`D:/Ptvbox`；Windows PCBOX仅只读参考，没有修改。应用显示名为 **Ptvbox**，包名、签名身份和SQLite版本3保持；0.4.0/versionCode 6。目标是迁移PCBOX 1.1.4详情和设置的内容顺序、交互逻辑，再使用Android/TV组件实现，不等于所有PC功能已移植。

## 本版实现清单

- [x] 应用标题改为Ptvbox；保留用户提供的图形Logo、现有深浅主题和TV导航。
- [x] 详情顺序：背景横幅与标题 → 海报/事实/双评分/日期/操作 → 季与单集 → 作品资料与播放线路 → 出品与播出 → 简介 → 人物 → 同系列 → 相关版本 → 相似推荐。空模块隐藏。
- [x] 永久保留豆瓣/TMDB各自的手动匹配和清除按钮；关联后分数、人数和人物资料在当前页更新，清除不连带删除另一平台的关联。
- [x] 豆瓣片名候选补充与PC相同的全文查询路径；别名、原名和季名参与候选，歧义不强制关联；数字ID保留。
- [x] 豆瓣日期支持数组/字符串，优先大陆日期并校验有效日历日期；TMDB日期、绿字和未上映标识保留。
- [x] 季海报、单集图片/评分/人数/日期/简介、单集收藏/已看/进度和独立播放；季切换不改变原作品身份，豆瓣不同季的关联隔离。
- [x] 详情人物头像的提供方身份区分，支持人物作品、出品方作品、TMDB合集、相关版本和推荐。人物/公司拓展查询需要有效TMDB Key，不能唯一识别时说明原因。
- [x] “刷新全部资料”重新获取元数据与目录，并使图片缓存键更新；不清收藏和历史。
- [x] 片源卡片自适应网格、已知容量升序/未知末尾、多选绿色分辨率筛选、原始标签HDR/Dolby Vision/Atmos；标签不冒充实际解码检测。
- [x] 默认先看详情再播放；普通目录可以独立查询且不依赖TMDB Key，默认不在进入详情时并发扫全部来源。
- [x] 设置改成13类左导航/右侧虚拟内容，各分类保留滚动位置；输入支持触摸/鼠标和遥控器，不自动弹出首个Key输入框键盘。
- [x] 电视轻量/均衡/高性能/自动档位；图片内存、磁盘缓存、播放缓冲和默认并发有明确上限。6/12/20路搜索档位，用户可以单独改并发。
- [x] 主评分提供方、副评分显示、固定导航、搜索展示样式、默认查询站点和详情目录预取设置接入实际状态。
- [x] 播放倍速、原始/拉伸/裁切、启动超时、全局片头片尾秒数、默认保存停止行为和可选后台播放服务。
- [x] 高清优先比较首批候选，恢复播放保护之前清晰度；已知更低版本不自动接续，实际解码降级也拒绝，手动切换仍允许。
- [x] MediaSession媒体服务拥有进程级播放器；默认系统HOME保存停止释放，应用内浏览保留。后台开关开启才允许系统后台继续，最近任务移除仍保存停止。
- [x] 内嵌文字字幕自定义字号、字体、粗体、文字颜色/不透明度、背景不透明度和中英预览；关闭自定义恢复默认样式。图片字幕不更换字体。
- [x] SubDL、ASSRT、OpenSubtitles、自建弹幕/弹弹play、GitHub凭据入口加密保存/删除及已保存标识；不回显密钥。在线字幕与弹幕执行器尚未迁移，界面明确说明。
- [x] 站点页紧凑稳定key虚拟列表、分组/名称筛选、单站和整组即时开关、分组优先级；已关闭站点的迟到搜索结果不重新加回。
- [x] 单组/全部接口检测、完成数量、取消和逐站状态；区分不支持规则、配置可读、接口有响应和失败，不把HTTP成功说成能播放。
- [x] 私人订阅变更列表预览，确认后激活，可取消/回退；校验失败或现用配置变化时不覆盖，站点开关保留。
- [x] 云端维护清单签名与路径/hash格式验证、组件更新详情/上游健康预览；PC动画规则执行器未适配Android，因此不激活该规则包。
- [x] 手机临时HTTPS配置台扩展服务凭据、电视档位、并发和搜索/播放暂停/停止命令；原授权、到期撤销和禁止读回凭据保持。
- [x] AES-GCM密码加密的可携带备份；还原先预览再合并，保留本地稳定ID、现有凭据和较新进度；不导出Keystore私钥或系统桌面ID。
- [x] 网络超时、User-Agent、可选HTTP/SOCKS5代理和DoH；应用设置不会取消已经工作的请求，默认关闭代理/DoH。
- [x] 无痕模式避免新增观看/搜索记录；缓存清理保留订阅、密钥、收藏和历史。
- [x] Android专属更新入口：只查已发布APK，SHA-256/包名/签名/版本校验，已下载包复用、进度、取消、系统安装确认和导出安装包；没有更新时不覆盖。

## 数据与回退风险

1. 新字段均为JSON可选字段，旧记录默认值保持；SQLite schema不升级，毫秒进度、UUID、独立单集标记、收藏及ATV ID保留。
2. 手动关联按平台独立，跨季豆瓣采用额外键，不覆盖旧平台键；不能唯一匹配不强行合并。
3. 还原采用加法合并，保留已有凭据和较新进度；无法解密/格式错误不删除原数据。恢复订阅后首次Jar加载仍可能慢。
4. APK必须原签名覆盖安装，禁止卸载/清数据。0.3.0和0.2.2包保留；降级APK不能保证系统允许，应优先保留当前数据并使用修复版本。
5. 20路并发增加请求、TLS和Jar压力；低内存电视建议自动/轻量，用户仍可手动选20路。并发上限不代表每站响应更快。
6. 图片/缓冲档位在重启后完整生效；更改不会强行中断当前播放。在线更新安装仍需要Android系统确认。
